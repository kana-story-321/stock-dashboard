# 引き継ぎメモ：ワクワクルーレット

別リポジトリで開発を続けるためのメモです。コードは `roulette/` フォルダ一式をそのまま移せば動きます。

- 元の場所：`kana-story-321/stock-dashboard` の `claude/roulette-app` ブランチ、`roulette/` フォルダ
- 状態：機能は一通り完成。ヘッドレスブラウザで、デモモードでの動作を PC 幅とスマホ幅で確認済み
- 未確認：本物の Google ログインと Firestore への保存（Firebase の設定値がまだないため）

## 1. 要件（ユーザーの依頼）

1. 好きな候補でルーレットを作れる
2. スタート／ストップでランダムに当たりが決まる
3. 見ていてワクワクする楽しい UI
4. ルーレットを複数持てて、事前に登録しておける
5. Google アカウントでのログインを必須にする
6. 公開先は ai-mottainai.jp のドメイン（後述の「残作業」参照）

## 2. 構成

ビルド不要の静的サイトです。フレームワークも npm も使っていません。

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨組み（ログイン画面／アプリ画面／結果モーダル／紙吹雪 canvas／トースト） |
| `style.css` | 見た目。ダーク紫＋ネオン系、レスポンシブ（1100px・760px で切替） |
| `app.js` | ロジック一式（ES Module）。約1100行 |
| `firebase-config.js` | Firebase 設定値。**現在は空**（空だとデモモードになる） |
| `firestore.rules` | Firestore セキュリティルール（本人のデータのみ読み書き可） |
| `README.md` | 利用者向けの説明とセットアップ手順 |

外部依存は2つだけです。

- Firebase JS SDK 10.12.2（`https://www.gstatic.com/firebasejs/10.12.2/` から動的 import。Firebase 設定があるときだけ読み込む）
- Google Fonts「M PLUS Rounded 1c」

ES Modules を使っているため、ファイルを直接開くのではなく HTTP サーバー経由で開く必要があります（例：`python3 -m http.server`）。

## 3. app.js の中身

上から順に、次のブロックに分かれています。

1. **定数・テンプレート**：配色パレット12色、テンプレート6種（ランチ／罰ゲーム／順番決め／家事当番／YES・NO／週末）
2. **バックエンド層**：同じインターフェース（`onUser / signIn / signOut / list / save / remove`）を持つ2つの実装
   - `createFirebaseBackend()`：Firebase Auth（Google、`signInWithPopup` が失敗したら `signInWithRedirect`）＋ Firestore
   - `createLocalBackend()`：localStorage に保存するデモモード。`firebase-config.js` が空のときだけ使う
3. **sound**：Web Audio で効果音を合成（音声ファイルは使わない）。カチカチ音・スタート音・ファンファーレ。ON/OFF は localStorage に保存
4. **confetti**：画面全体の canvas に紙吹雪を出す
5. **wheel**：ルーレットの描画と回転（下で詳しく説明）
6. **bulbs**：ホイールの周りの電飾28個。待機中はゆっくり交互、回転中は流れる、当たりで点滅
7. **状態管理・保存**：`state`、保存は600msのデバウンス。ページを離れるときは `flushSaves()` で即保存
8. **DOM 描画**：一覧・候補エディタ・履歴。XSS 対策として、すべて `textContent` で描画（innerHTML は使わない）
9. **イベント・ログイン処理**：`main()` から開始

### 抽選と回転の仕組み（大事なところ）

- 回転の状態は `idle → accel（加速）→ cruise（一定速度）→ decel（減速）→ idle` と進む
- **当たりはストップを押した瞬間に決まる**。重み付きランダムで、乱数は `crypto.getRandomValues` を使う
- 当たりの扇形の中の位置（両端12%は避ける）をランダムに選び、そこで針がぴったり止まるように減速カーブを逆算する
  - 減速は ease-out quart（4乗）なので、最後にじわじわ止まる
  - 止まるまで4〜6秒。減速の始まりの速さが cruise 時と一致するように所要時間を計算しているので、ガクッとならない
- 加速中にストップを押した場合は、受け付けておいて cruise に入った時点で減速を始める
- 針は真上（角度 −π/2）。針の下の扇形が変わるたびにカチカチ音を鳴らし、針を揺らし、候補名を表示する
- 回転中は候補の編集とルーレットの切替を無効化する（形が変わると止まる位置がずれるため）
- 候補が2つ以上ないとスタートできない

## 4. データモデル（Firestore）

保存場所：`users/{uid}/roulettes/{rouletteId}`

```json
{
  "id": "uuid",
  "name": "今日のランチ",
  "items": [
    { "id": "uuid", "label": "ラーメン", "color": "#ff4fa3", "weight": 1, "excluded": false }
  ],
  "history": [{ "label": "ラーメン", "at": 1730000000000 }],
  "removeWinner": false,
  "createdAt": 1730000000000,
  "updatedAt": 1730000000000
}
```

| 項目 | 内容 |
|---|---|
| `weight` | 当たりやすさ 1〜10。扇形の角度もこの比率になる |
| `excluded` | 「当たった候補は次回から外す」で外された候補。データは残り、「外した候補を戻す」で復活できる |
| `history` | 新しい順、最大50件 |

上限は、名前40文字・候補200件・履歴50件です。ルール側でも同じ上限をチェックしています。

読み込み時は `normalizeRoulette()` で値を整えます（不正な色・重みの補正など）。ルーレットが0件のユーザーには「今日のランチ」を自動で作ります。

## 5. 決めたこと

- **ログイン必須の扱い**：Firebase が設定されていれば Google ログインが必須。設定がないときだけ、ログイン画面にデモモードのボタンが出る（開発・確認用）
- **ホイールの文字**：扇形に沿って放射状に書く（実物のルーレットと同じ）。左半分は逆さまになるが、回転するので許容した
- **当たりの決め方**：物理演算に任せず、先に決めて止まる位置を逆算する。公平さと確実さを優先
- **データの保存先**：ユーザーごとの Firestore サブコレクション。共有機能は今は無い

## 8. 動作確認の方法

Playwright（Chromium）で次の流れを確認しました。

1. ログイン画面を表示
2. デモモードでログイン
3. 候補を追加
4. スタート → ストップ
5. 結果モーダルの当たりと、針が指す候補が一致することを確認
6. 再読み込みしても候補と履歴が残っていることを確認
